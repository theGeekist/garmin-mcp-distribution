# Changing Garmin data

Use the installed tool schema and current record data. Verify write access through the host if required. A request to plan or analyse an activity stays read-only. A request to save, change or delete data starts the tool's review and confirmation flow.

- **Create a running or cycling workout.** Call `garmin_preview_workout`. Present the returned workout with all intervals, repetitions, durations, target ranges and units. State that the preview is unsaved. After the user explicitly confirms those values, call `garmin_create_workout` with the identical workout, its preview confirmation and `confirmed: true`. Preview and confirm again if the workout changes or the preview expires. For an ambiguous creation result, use `garmin_get_workout` if the server returns an ID or inspect the workout library before considering any further write.
- **Update an activity.** Read its current details. Present the exact changes with before and after values. After explicit confirmation, call `garmin_update_activity` for the resolved ID and only the requested fields. Use metres and seconds as required by the schema.
- **Create a manual activity.** Resolve the activity type (use `garmin_activity_types` as needed), local date and time, IANA time zone, distance and duration. Show those values and the name before asking for explicit confirmation. Call `garmin_create_activity` with the confirmed values.
- **Import an activity file.** Verify the user-supplied FIT, GPX or TCX file and the requested upload mode. Show the filename and mode, then call `garmin_upload_activity` only after explicit confirmation. Pass the file bytes through the tool where supported. Keep base64 and raw location data out of chat.
- **Delete an activity or workout.** Resolve the current record and show the exact item and the deletion consequence. After explicit confirmation, use `garmin_delete_activity` or `garmin_delete_workout` with its ID and `confirmed: true`.
- **Disconnect.** Use `garmin_disconnect_account` only for an explicit request to disconnect the hosted Garmin account. Distinguish that from removing the MCP connection in the host and revoking a Garmin Personal API key. Explain the hosted credential and session removal before the call. Respect the host's approval prompt if shown.

Use the response's `outcome`, `status` and `code` where available. Report success only when confirmed by the service. On an uncertain result, verify through a supported read-back path or tell the user what to check in Garmin Connect. Never automatically repeat an uncertain Garmin write or infer deletion from a timeout, null or missing page.
